# Механика

Двумерная физическая песочница: React и Canvas для редактора, собственный C++17-движок в WebAssembly. Расчёт работает в Web Worker с постоянным состоянием и числовыми буферами; отдельный C++-процесс и HTTP-шаг симуляции не используются.

## Запуск и сборка

Нужны Node.js и npm. Для пересборки движка нужен активированный Emscripten SDK: скрипт использует `EMSDK` либо `~/.local/share/emsdk`, при необходимости `EMSDK_PYTHON`. В macOS автоматически выбирается Python, поставляемый с SDK. Текущая конфигурация сборки рассчитана на Emscripten 6.0.9. Для нативных тестов нужен C++17-компилятор `g++` или путь в `CXX`.

```sh
cd frontend
npm ci
npm run dev
```

`npm run dev`, `npm run build` и `npm test` сначала проверяют хеш исходников WASM и пересобирают его при изменениях. Если хеш совпадает с `public/engine/build.json`, SDK не нужен. Иначе отсутствие SDK останавливает команду: старый бинарный файл не выдаётся за новую сборку.

```sh
npm run build
npm run preview
```

Каталог `frontend/dist` содержит статический сайт, Worker и файлы движка. Его нужно обслуживать по HTTP(S), а не открывать через `file://`.

Для проверки интерфейса с уже имеющимся бинарным файлом можно отдельно запустить `npx vite`; это не подтверждает актуальность WASM. Клиент отдельно собирается командой `npx tsc -b && npx vite build`.

## Редактор

- Координаты и размеры — в метрах; ось Y направлена вниз. Сетка 1 м, привязка 0,1 м. Камера перемещается без границ, колесо масштабирует относительно курсора, кнопка центрирования охватывает систему.
- Тела и круги имеют общий счёт индексов от 1; рычаги, подшипники, пружины и другие типы — отдельные. Внутренний ID сохраняет ссылки при изменении видимого индекса. Старые проекты получают индексы при импорте.
- Угловые и боковые маркеры меняют размеры относительно неподвижного противоположного угла/стороны. Круг сохраняет круговую форму. Отдельный маркер вращает тело с шагом 5°.
- Рычаг и поверхность редактируются двумя концами. Толщина рычага после изменения концов — 0,12 м, стандартный диаметр подшипника — 0,16 м. Поверхность изображается линией со штриховкой, которая вращается вместе с ней.
- Силы, скорости и ускорения назначаются выбранным телам, всем существующим либо всем, включая будущие. Объект воздействия появляется после подтверждения. Модуль и связанные ориентированные углы задают вектор; проекции X/Y вычисляются.
- Ускорение свободного падения — удаляемое воздействие, скрытого дополнительного g нет. Скорость задаёт начальную скорость; её редактирование при запуске меняет скорости получателей.
- Крепления хранят точки в локальных координатах. Рычаг крепится концами; подшипник допускает вращение и может стоять внутри рычага. Пружина и нить сохраняют свои законы.
- Симуляция запускается кнопкой. Остановка восстанавливает снимок сцены. Во время расчёта перетаскивание прикладывает силу, а не задаёт координаты напрямую.
- Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z и Delete. Импорт/экспорт JSON сохраняет индексы и связи.

## Расчёт и ограничения

Фиксированный шаг — 1/240 с с адаптивными подшагами; отрисовка использует requestAnimationFrame и историю состояний. При перегрузке ограничивается догоняющая работа, физический шаг не увеличивается. Частота кадров зависит от дисплея и нагрузки.

Движок учитывает силы, моменты инерции, вращение, контакты, трение, пружины, шарниры, жёсткие соединения и нити. Для блока реализованы обхват нити и инерция вращения. Формулы x(t), y(t), φ(t) разбираются в C++, скорости и ускорения определяются производными. Поиск статики использует динамическую релаксацию; невязка оценивается до искусственного затухания.

Это численная модель с ограничениями:

- Поверхность участвует в контактах как конечный отрезок по видимой линии, с обеих сторон и при любом наклоне. Сохранённая толщина старых проектов определяет положение линии относительно центра, но не создаёт невидимую стенку.
- Изменение размеров связанных сборок, сложные контакты и крайние соотношения масс требуют дополнительных проверок. Полной гарантии отсутствия проникновения при быстрых столкновениях нет.
- При требовании более 256 подшагов расчёт сообщает ошибку, а не увеличивает шаг.
- Малые векторы рисуются с непрерывно уменьшающейся длиной, без искусственного минимального размера. Величины усреднены за последний физический шаг; их соответствие интерполированному изображению и численные колебания на контактах ещё проверяются.
- Проверки импульса и энергии покрывают перечисленные ниже сценарии, а не все возможные сочетания связей, столкновений и заданных движений. Полный аудит и вращательные балансы ещё не завершены.

Актуальные требования и результаты блоков — в [TASKS.md](TASKS.md).

## Проверки

Из `frontend`:

```sh
npm test
npm run lint
npm run build
```

При отсутствии SDK можно разделить проверки:

```sh
node tests/check.mjs
node tests/wasm.mjs
npx tsc -b
```

`check.mjs` проверяет модель, миграцию, индексы, ссылки, геометрию и компилирует нативные C++-тесты. `wasm.mjs` проверяет имеющийся WASM-файл; без пересборки это не доказывает его совпадение с исходниками.

Совместные сценарии включают свободное падение, работу постоянной силы, прямые удары разных масс при e = 0/0,5/1, пружину без потерь и с демпфированием. Тест пружины сравнивает шаги 0,001 и 0,0005 с: максимальный дрейф энергии за 4 с меньше 0,003 Дж и уменьшается примерно вдвое. При демпфировании ошибка баланса механической энергии и диссипации меньше 0,002 Дж. Допуски записаны в тестах.

WASM-тесты также охватывают траектории, независимость от частоты кадров, вес и реакции, поиск равновесия, рычаги, блок, контактные штабели и нагрузочные замеры.

Примеры проектов находятся в `examples/`: `default`, `lever`, `spring-wasm`, `atwood`, `moving-platform`, `static-beam` (файлы `.physics.json`).

### Установка Emscripten

```sh
git clone https://github.com/emscripten-core/emsdk.git ~/.local/share/emsdk
~/.local/share/emsdk/emsdk install 6.0.9
~/.local/share/emsdk/emsdk activate 6.0.9
source ~/.local/share/emsdk/emsdk_env.sh
cd frontend
npm test
npm run build
```

Первичная установка SDK требует Python 3.10 или новее (путь можно задать через `EMSDK_PYTHON`). После установки macOS SDK содержит собственный Python. Активация через `source` нужна для прямого вызова `em++`; команды npm находят стандартный каталог самостоятельно.

## Docker и GitHub CI/CD

```sh
docker compose up --build -d
# Остановить:
docker compose down
```

Откройте `http://localhost:8080`. По умолчанию Docker Compose, `npm run dev` и `npm run preview` слушают `0.0.0.0:8080`, поэтому сайт также доступен по IP компьютера в локальной сети. Занятый порт вызывает ошибку, а не молчаливый переход на другой порт. Сборка использует Emscripten 6.0.9 и Node.js 24, заново компилирует WASM и выполняет `npm test`, lint и production-сборку. Локальные `node_modules`, `dist` и готовые WASM-файлы не попадают в контекст. Итоговый образ содержит nginx и статические файлы; SDK и Node.js для работы сайта не нужны.

`.github/workflows/ci.yml` запускает ту же Docker-сборку на PR, push в `main`, тегах `v*` и вручную. После сборки проверяет HTTP-раздачу HTML, загрузчика движка и WASM. Только успешные push-сборки публикуются в Docker Hub: `astonikum/sandbox:latest` для основной ветки, тег коммита `sha-…` и версии `v…`. Для публикации добавьте в GitHub Actions секрет `DOCKERHUB_TOKEN`: токен Docker Hub пользователя `astonikum` с правом записи в `astonikum/sandbox`. Токен хранится только в GitHub Secrets. Без токена сборка и тесты выполняются, публикация пропускается с пояснением в отчёте CI. Развёртывание на внешний сервер не настроено.

Запуск опубликованного образа (после первой успешной публикации):

```sh
docker run --rm -p 8080:80 astonikum/sandbox:latest
```

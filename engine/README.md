# Физический движок

Движок написан на C++17. Одна библиотека используется в нативных тестах и в WebAssembly. Фронтенд общается с ней через прежние функции `engine_*`; внутренние классы и имена полей не входят в этот протокол.

## Сборка и проверка

Из корня репозитория:

```sh
node engine/test.mjs
node engine/build-wasm.mjs
npm --prefix frontend test
npm --prefix frontend run build
```

Для нативных тестов нужны Node.js и компилятор C++17. По умолчанию используется `g++`, другой компилятор задаётся переменной `CXX`. Для WASM нужен Emscripten: `EMSDK` либо `~/.local/share/emsdk`; `EMSDK_PYTHON` позволяет выбрать Python. Скрипт передаёт выбранный Python также вложенным вызовам компилятора. Сборка использует LTO, чтобы сохранить оптимизацию между отдельными `.cpp`.

Вариант без Node.js для нативной библиотеки и тестов:

```sh
cmake -S engine -B engine/build/native -DCMAKE_BUILD_TYPE=Release
cmake --build engine/build/native --parallel
ctest --test-dir engine/build/native --output-on-failure
```

Цель `mechanics_core` — библиотека, `physics` — утилита обмена состоянием через stdin/stdout. Проверки вынесены из прежнего `physics --test` в отдельные исполняемые тесты; их запускает CTest или `node engine/test.mjs`. Проверки `assert` остаются включены и при Release-сборке тестов.

Исходники `.cpp` в `src` включаются в сборку автоматически. `main.cpp` относится только к нативной утилите, `wasm.cpp` — только к WASM. Хеш WASM учитывает исходники, заголовки и скрипт сборки. После изменения C++ необходимо пересобрать `frontend/public/engine`; запуск Vite сам по себе этого не делает.

## Устройство

| Модуль | Ответственность |
| --- | --- |
| `math.hpp` | `Vec2`, скалярное и векторное произведения, поворот |
| `body.hpp/.cpp` | Тела, связи, масса и инерция, применение и учёт импульсов |
| `geometry.hpp/.cpp` | Проекции фигур, опорные грани и геометрия поверхности |
| `broadphase.hpp/.cpp` | Поиск потенциальных пар и исключение соединённых тел |
| `collision.hpp/.cpp` | Нормаль, точки контакта, накопленные контактные импульсы, совместное решение реакции и трения, качение |
| `constraints.hpp/.cpp` | Шарнир, сварное соединение, нить, идеальный и инерционный блок |
| `rest.hpp/.cpp` | Проверка устойчивого покоя и подавление остаточных скоростей |
| `solver.hpp/.cpp` | Подшаг: силы, пружины, движение, связи, контакты, покой |
| `expression.hpp/.cpp` | Разбор формул и вычисление значения с двумя производными |
| `history.hpp/.cpp` | Кольцевая история и интерполяция состояния |
| `runtime.hpp/.cpp` | Владение состоянием, время, адаптивные подшаги и траектории |
| `scene.cpp` | Проверка входных буферов, создание и редактирование сцены |
| `observables.cpp` | Ускорения, силы, моменты, выборка сил и статическая релаксация |
| `protocol.hpp` | Размеры буферов, номера полей, лимиты и коды результата |
| `wasm.cpp` | Тонкие обёртки `extern "C"` над одним экземпляром `Runtime` |

Заголовки содержат типы и объявления. Реализации находятся в `.cpp`; небольшие операции с векторами и доступа к данным остаются inline. `core.hpp` — общий вход в низкоуровневое ядро.

`Runtime` владеет телами, связями, силами, формулами, историей и `Solver`. `Solver` владеет временными буферами, `BroadPhase` и `ContactSolver`. Изменяемое состояние не разделяется между экземплярами. В WASM единственный экземпляр находится внутри адаптера `wasm.cpp`. История занимает несколько мегабайт: нативные экземпляры `Runtime` следует размещать в динамической памяти, например через `std::make_unique<Runtime>()`.

Источник импульса передаётся аргументом. Индекс связи неотрицателен; контакт получает `-1 - (first * bodyCount + second)`. Силы группируются по источнику, категории и слоту. У блока слоты 1 и 2 различают ветви нити. Этот порядок нужен для стабильного отображения сил.

## Порядок расчёта

Один `Runtime::advance` продвигает время на 1/240 секунды. Сначала сохраняются начальные скорости и очищаются накопленные импульсы. Размер подшага ограничивается движением потенциально сталкивающихся тел, жёсткостью и демпфированием пружин. Максимум — 256 подшагов.

На каждом подшаге обновляются заданные траектории, затем `Solver::step` выполняет:

1. Внешние силы, гравитацию и перетаскивание.
2. Импульсы пружин.
3. Восстановление и уточнение импульсов сохранившихся контактов до перемещения тел.
4. Интегрирование положений и углов.
5. Подготовку новых контактов и 24 итерации связей и контактов; пары обновляются каждые четыре итерации.
6. Запись итоговых контактных сил и проверку остаточного движения.

Каждая итерация пересчитывает суммарные импульсы контакта и прикладывает разницу с предыдущим приближением. Поэтому решатель может исправлять завышенную реакцию, а предел трения считается от полной нагрузки. Между подшагами сохраняется начальное приближение для совпадающих контактов с масштабированием по длительности шага. Отскок задаётся при подготовке контакта, а не добавляется заново каждой итерацией. Исчезнувшие контакты удаляются, сброс сцены очищает кеш.

Предварительное уточнение существующих контактов нужно для покоя на наклонной поверхности: иначе сила тяжести успевает сдвинуть тело до расчёта реакции, даже когда итоговая скорость равна нулю. Силы для отображения записываются по окончательному импульсу, а не по сумме абсолютных итерационных поправок. Порядок источников детерминирован. Паразитное трение и компоненты ускорения в пределах машинной погрешности обнуляются относительно масштаба расчёта; временное сглаживание и минимальная отсечка физических сил не применяются.

После подшагов проверяется конечность состояния, рассчитываются наблюдаемые величины и записывается история. Порядок операций и пар влияет на численный результат: менять его следует вместе с проверками физики.

Единицы — метры, секунды, килограммы и радианы. Ось Y направлена вниз. Фиксированное тело не перемещается, но фиксированный блок может вращаться. Кинематическое тело получает положение и скорость из формул и не меняет их от импульсов.

## Контракт с фронтендом

Входной буфер — `double`: сначала резерв для 200 тел по 17 чисел, затем резерв для 400 связей по 16 чисел. Связи всегда начинаются со смещения `200 * 17`, независимо от текущего количества тел.

Тело: `kind, x, y, width, height, angle, mass, friction, restitution, vx, vy, omega, motion, fx, fy, ax, ay`. Поле `motion`: 0 — динамика, 1 — фиксация, 2 — кинематика, 3 — фиксация с траекторией.

Связь: `kind, bodyA, bodyB, anchorX, anchorY, localAX, localAY, localBX, localBY, length, stiffness, damping, pulley, referenceAngle`, затем два резервных числа. Индекс `bodyB = -1` означает неподвижный мировой якорь.

Виды тел: прямоугольник 0, круг 1, блок 5, поверхность 9, стержень 10. Виды связей: шарнир 2, пружина 3, нить 4, блок 10, сварное соединение 12. Имена этих значений объявлены в `body.hpp`.

Состояние на выходе: `x, y, angle, vx, vy, omega` — шесть чисел на тело. История хранит 512 записей. В гладких участках применяется кубическая интерполяция Эрмита, около скачков скорости — линейная.

Наблюдаемые величины — 20 чисел: по две компоненты ускорения, гравитации, нормальной силы, трения, пружины, шарнира, нити, результирующей силы и веса; затем момент и угловое ускорение. Выборка сил — семь чисел: индекс тела, категория, локальная точка X/Y, сила X/Y и идентификатор источника. `collectForceSamples` обновляет буфер перед чтением.

Формулы передаются тремя строками по 256 байт, включая нулевой терминатор: X, Y и угол. Поддерживаются `t`, `pi`, `+`, `-`, `*`, `/`, `^`, скобки, `sin`, `cos`, `exp`, `log`, `sqrt`.

| Код | Значение |
| --- | --- |
| 0 | Успех |
| 1 | Некорректный запрос или недоступное время истории |
| 2 | Ошибка формулы или исключение во время шага |
| 3 | Требуется больше допустимого числа подшагов |
| 4 | Некорректное численное состояние |

После ошибки шага 2–4 требуется `reset`. Не меняйте номера, порядок полей и экспортируемые функции при внутреннем рефакторинге.

## Как вносить изменения

Новую геометрию добавляйте в `geometry.cpp` и построение контакта. Новый тип связи — в отдельную функцию внутри `constraints.cpp` и её диспетчер. Закон силы — в соответствующий этап `solver.cpp`; импульсы проводите через `applyImpulse`, чтобы измеряемые силы оставались согласованы с движением. Новое редактируемое поле требует согласованного изменения протокола и Worker, поэтому это отдельная задача от рефакторинга ядра.

Изменение закона проверяйте сценой с известным результатом: свободное падение, столкновение, равновесие, баланс импульса или энергии. Для рефакторинга сравнивайте одинаковые сцены до и после. `tests/runtime.cpp` проверяет независимость экземпляров, историю, сброс и траектории; `tests/rest.cpp` — остановку и возобновление движения. `tests/stability.cpp` проверяет покой стопки, отсутствие ползучести после падения на склон, равномерное и ускоренное скольжение прямоугольника, стабильность точек приложения сил и сохранение реальных малых ускорений. Проверки фронтенда дополнительно прогоняют собранный WASM и настоящий Worker.

Форматирование: `clang-format -i engine/src/*.hpp engine/src/*.cpp engine/tests/*.cpp`. Настройки находятся в `engine/.clang-format`. Объяснения алгоритмов и ограничения храните в этом документе; код пишется без комментариев.

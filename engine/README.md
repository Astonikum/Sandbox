# Физический движок

Движок написан на C++17. Одна библиотека используется в нативных тестах и в WebAssembly. Фронтенд общается с ней через прежние функции `engine_*`; внутренние классы и имена полей не входят в этот протокол.

## Сборка и проверка

Из корня репозитория:

```sh
node engine/test.mjs
node engine/build-wasm.mjs
npm --prefix frontend test
npm --prefix frontend run build
```

Для нативных тестов нужны Node.js и компилятор C++17. По умолчанию используется `g++`, другой компилятор задаётся переменной `CXX`. Для WASM нужен Emscripten: `EMSDK` либо `~/.local/share/emsdk`; `EMSDK_PYTHON` позволяет выбрать Python. Скрипт передаёт выбранный Python также вложенным вызовам компилятора. Сборка использует LTO, чтобы сохранить оптимизацию между отдельными `.cpp`.

Вариант без Node.js для нативной библиотеки и тестов:

```sh
cmake -S engine -B engine/build/native -DCMAKE_BUILD_TYPE=Release
cmake --build engine/build/native --parallel
ctest --test-dir engine/build/native --output-on-failure
```

Цель `mechanics_core` — библиотека, `physics` — утилита обмена состоянием через stdin/stdout. Проверки вынесены из прежнего `physics --test` в отдельные исполняемые тесты; их запускает CTest или `node engine/test.mjs`. Проверки `assert` остаются включены и при Release-сборке тестов.

Исходники `.cpp` в `src` включаются в сборку автоматически. `main.cpp` относится только к нативной утилите, `wasm.cpp` — только к WASM. Хеш WASM учитывает исходники, заголовки и скрипт сборки. После изменения C++ необходимо пересобрать `frontend/public/engine`; запуск Vite сам по себе этого не делает.

## Устройство

| Модуль | Ответственность |
| --- | --- |
| `math.hpp` | `Vec2`, скалярное и векторное произведения, поворот |
| `body.hpp/.cpp` | Тела, связи, масса и инерция, применение и учёт импульсов |
| `geometry.hpp/.cpp` | Проекции фигур, опорные грани и геометрия поверхности |
| `broadphase.hpp/.cpp` | Поиск потенциальных пар и исключение соединённых тел |
| `collision.hpp/.cpp` | Нормаль, точки контакта, накопленные контактные импульсы, совместное решение реакции и трения, качение |
| `constraints.hpp/.cpp` | Шарнир, сварное соединение, нить, идеальный и инерционный блок |
| `ccd.hpp/.cpp` | Непрерывный поиск момента столкновения при перемещении и вращении |
| `rest.hpp/.cpp` | Проверка устойчивого покоя и подавление остаточных скоростей |
| `solver.hpp/.cpp` | Подшаг: силы, пружины, движение, связи, контакты, покой |
| `expression.hpp/.cpp` | Разбор формул и вычисление значения с двумя производными |
| `history.hpp/.cpp` | Кольцевая история и интерполяция состояния |
| `runtime.hpp/.cpp` | Владение состоянием, время, адаптивные подшаги и траектории |
| `scene.cpp` | Проверка входных буферов, создание и редактирование сцены |
| `observables.cpp` | Ускорения, силы, моменты, выборка сил и статическая релаксация |
| `protocol.hpp` | Размеры буферов, номера полей, лимиты и коды результата |
| `wasm.cpp` | Тонкие обёртки `extern "C"` над одним экземпляром `Runtime` |

Заголовки содержат типы и объявления. Реализации находятся в `.cpp`; небольшие операции с векторами и доступа к данным остаются inline. `core.hpp` — общий вход в низкоуровневое ядро.

`Runtime` владеет телами, связями, силами, формулами, историей и `Solver`. `Solver` владеет временными буферами, `BroadPhase` и `ContactSolver`. Изменяемое состояние не разделяется между экземплярами. В WASM единственный экземпляр находится внутри адаптера `wasm.cpp`. История занимает несколько мегабайт: нативные экземпляры `Runtime` следует размещать в динамической памяти, например через `std::make_unique<Runtime>()`.

Источник импульса передаётся аргументом. Индекс связи неотрицателен; контакт получает `-1 - (first * bodyCount + second)`. Силы группируются по источнику, категории и слоту. У блока слоты 1 и 2 различают ветви нити. Этот порядок нужен для стабильного отображения сил.

## Порядок расчёта

Один `Runtime::advance` продвигает время на 1/240 секунды. Сначала сохраняются начальные скорости и очищаются накопленные импульсы. Базовый подшаг — 1/1920 секунды; жёсткость и демпфирование пружин могут уменьшить его. Для траекторий дополнительно учитываются линейное и угловое ускорения в начале, середине и конце такта, чтобы ограничить ошибку интерполяции. Максимум — 256 подшагов. Высокая линейная скорость сама по себе больше не требует дробления шага.

`ccd.hpp/.cpp` выполняет непрерывный поиск столкновений кругов и прямоугольников, включая конечные поверхности. BroadPhase отбирает пары по границам всего перемещения с запасом на вращение. По разделяющей оси вычисляется безопасное продвижение до контакта; при вращении учитываются интервалы смены опорной вершины. После 128 приближений используется ограниченное разбиение временных интервалов (до 4096 проверок). Дополнительная граница расстояния на вращающейся вместе с телом оси учитывает кривизну относительного движения и позволяет быстро исключать почти касательные проходы совместно вращающихся тел. Численный допуск проникновения при поиске — 1e-7 м.

Решатель перемещает тела до первого столкновения, рассчитывает контактные импульсы и повторяет поиск на оставшемся времени с новыми скоростями. На подшаг допускается до 64 событий. Импульсы завершённого контакта записываются в учёт сил; начальные приближения остальных контактов сохраняются.

Перед движением начальные перекрытия устраняются отдельными позиционными проходами (до 96). Поправка распределяется по обратным массам; скорости и журнал физических импульсов от неё не изменяются. Целевой остаток — 1e-5 м, критерий завершения восстановления — не более 2e-5 м. Если свободного места нет или проходы не сходятся, расчёт возвращает код 3.

Если выталкивание упирается в другое подвижное тело, оставшаяся нормальная поправка распределяется между ними по обратным массам, затем пути снова проверяются. Это позволяет восстанавливать плотную сборку, не проталкивая её нижние тела сквозь опору. Поправки, у которых перемещение каждой точки тела не превышает 1e-12 м, отбрасываются целиком: они не накапливают непроверенное перемещение и не запускают дорогостоящий поиск CCD.

Позиционная поправка каждой связи и выталкивание каждого контакта проверяются CCD отдельно, включая поворот и тела блока. При встрече с препятствием ограничиваются поправки участвующих в ударе тел, после чего изменённые пути проверяются снова (до 64 проходов). Остальные тела, включая неколлидирующие стержни, сохраняют свободную поправку. Уже существующее перекрытие разрешено уменьшать; углубление ограничено численным допуском. Выталкивание из одного тела не переносит объект сквозь другое. Неподвижные и кинематические тела не смещаются восстановлением. При несовместимой связи и препятствии приоритет имеет непроникновение: связь может сохранить позиционную ошибку. Ручная перестановка тела задаёт новое начальное состояние, а не непрерывный путь от старого положения.

Кинематические траектории внутри подшага представлены линейным перемещением и поворотом между заданными положениями; в конце восстанавливаются точные положение и производные формул. Выборка ускорения в трёх точках не гарантирует точность для произвольной высокочастотной формулы. При превышении бюджета подшагов, событий или неразрешённом поиске столкновения возвращается код 3, после которого нужен сброс сцены; незавершённое движение не продолжается вслепую.

На каждом подшаге обновляются заданные траектории, затем `Solver::step` выполняет:

1. Внешние силы, гравитацию и перетаскивание.
2. Импульсы пружин.
3. Устранение начальных перекрытий с проверкой пути поправок, восстановление и уточнение импульсов сохранившихся контактов.
4. Непрерывный поиск столкновений, обработку ударов и интегрирование оставшегося движения.
5. Подготовку новых контактов и 24–96 итераций связей и контактов (число растёт с количеством связей); пары обновляются каждые четыре итерации.
6. Запись итоговых контактных сил и проверку остаточного движения.

Каждая итерация пересчитывает суммарные импульсы контакта и прикладывает разницу с предыдущим приближением. Поэтому решатель может исправлять завышенную реакцию, а предел трения считается от полной нагрузки. Между подшагами сохраняется начальное приближение для совпадающих контактов с масштабированием по длительности шага. Отскок задаётся при подготовке контакта, а не добавляется заново каждой итерацией. Исчезнувшие контакты удаляются, сброс сцены очищает кеш.

Предварительное уточнение существующих контактов нужно для покоя на наклонной поверхности: иначе сила тяжести успевает сдвинуть тело до расчёта реакции, даже когда итоговая скорость равна нулю. Силы для отображения записываются по окончательному импульсу, а не по сумме абсолютных итерационных поправок. Порядок источников детерминирован. Паразитное трение и компоненты ускорения в пределах машинной погрешности обнуляются относительно масштаба расчёта; временное сглаживание и минимальная отсечка физических сил не применяются.

После подшагов проверяется конечность состояния, рассчитываются наблюдаемые величины и записывается история. Порядок операций и пар влияет на численный результат: менять его следует вместе с проверками физики.

### Производительность

Защита позиционных поправок требует дополнительных проверок для каждой связи. Снимок положения сохраняется только для затронутых тел; для фигур без угловой поправки не вычисляется запас границ на вращение. Нагрузочные сцены со связями следует сравнивать отдельно: надёжность CCD имеет вычислительную стоимость даже при прежнем числе подшагов.

Матрица исключённых столкновений перестраивается только при изменении количества тел или топологии связей. Проверка сравнивает виды и индексы концов связей, поэтому замена сцены при прежнем количестве объектов также учитывается. Стержни исключаются до построения и сортировки габаритов. Если после интегрирования нет потенциальных контактов и непрерывных ограничений, пустые итерации решателя пропускаются.

Поиск пар выбирает ось обхода с учётом протяжённости сцены и размеров габаритов. Итоговые пары всегда сортируются по индексам тел. При неизменных положениях, углах, размерах, видах и признаках неподвижности используется прежний список пар. Изменение топологии связей также сбрасывает этот кеш.

Матрица эффективных масс контакта и коэффициент трения вычисляются при подготовке контактных точек. Проекции некруглых фигур сохраняются до изменения угла любого тела; на следующем подшаге кеш сбрасывается, чтобы учитывать редактирование размеров. Повороты локальных креплений используют уже сохранённые оси тела. Доступ к существующему контакту внутри итераций идёт через таблицу указателей, а порядок обхода и учёта сил сохраняется. После решения с точно нулевыми поправками импульсов повторное решение скоростей пропускается только при точном совпадении линейных и угловых скоростей обоих тел. Позиционные поправки продолжают выполняться. Изменения скорости и новый подшаг снимают эту оптимизацию. Число итераций непустого решателя, порядок пар, физические параметры и ABI сохранены.

Нагрузочный прогон: `node engine/benchmark.mjs`. Для сравнения с предыдущей сборкой сохраните вместе её `physics.mjs` и `physics.wasm`, затем выполните `node engine/benchmark.mjs /absolute/path/physics.mjs`. Скрипт измеряет только время физического такта после прогрева; вне замера проверяет конечность значений и побитовое совпадение состояний, наблюдаемых величин и выборок сил за все 480 тактов каждой сцены. Проверяются свободные тела, стопки, нити, шарниры, смешанные падающие фигуры, стержни и редактирование контакта. При намеренном изменении физики используйте `node engine/benchmark.mjs /absolute/path/physics.mjs --timing-only`: различия хешей выводятся, но не считаются ошибкой. Добавлена сцена повторных быстрых рикошетов. Нативные тесты CCD проверяют тонкие стены, вращение, встречные тела, углы, рикошеты, учёт импульсов, случайные вращательные проходы и перетаскивание сборки нитей с трением. Времена информационные: пороги зависят от компьютера и не используются как условия прохождения теста.

Единицы — метры, секунды, килограммы и радианы. Ось Y направлена вниз. Фиксированное тело не перемещается, но фиксированный блок может вращаться. Кинематическое тело получает положение и скорость из формул и не меняет их от импульсов.

Регрессии позиционного CCD проверяют восстановление начальных перекрытий без добавления скорости, распределение по массам, выталкивание возле стены, ограничение поступательных и вращательных поправок связей, скольжение вдоль стены, невозможное размещение и плотную сборку из 40 падающих фигур. Проверки WASM покрывают восстановление, связь через тонкую стену и отказ при невозможном размещении.

## Контракт с фронтендом

Входной буфер — `double`: сначала резерв для 200 тел по 17 чисел, затем резерв для 400 связей по 16 чисел. Связи всегда начинаются со смещения `200 * 17`, независимо от текущего количества тел.

Тело: `kind, x, y, width, height, angle, mass, friction, restitution, vx, vy, omega, motion, fx, fy, ax, ay`. Поле `motion`: 0 — динамика, 1 — фиксация, 2 — кинематика, 3 — фиксация с траекторией.

Связь: `kind, bodyA, bodyB, anchorX, anchorY, localAX, localAY, localBX, localBY, length, stiffness, damping, pulley, referenceAngle`, затем два резервных числа. Индекс `bodyB = -1` означает неподвижный мировой якорь.

Виды тел: прямоугольник 0, круг 1, блок 5, поверхность 9, стержень 10. Виды связей: шарнир 2, пружина 3, нить 4, блок 10, сварное соединение 12. Имена этих значений объявлены в `body.hpp`.

Состояние на выходе: `x, y, angle, vx, vy, omega` — шесть чисел на тело. История хранит 512 записей. В гладких участках применяется кубическая интерполяция Эрмита, около скачков скорости — линейная.

Наблюдаемые величины — 20 чисел: по две компоненты ускорения, гравитации, нормальной силы, трения, пружины, шарнира, нити, результирующей силы и веса; затем момент и угловое ускорение. Выборка сил — семь чисел: индекс тела, категория, локальная точка X/Y, сила X/Y и идентификатор источника. `collectForceSamples` обновляет буфер перед чтением.

Формулы передаются тремя строками по 256 байт, включая нулевой терминатор: X, Y и угол. Поддерживаются `t`, `pi`, `+`, `-`, `*`, `/`, `^`, скобки, `sin`, `cos`, `exp`, `log`, `sqrt`.

| Код | Значение |
| --- | --- |
| 0 | Успех |
| 1 | Некорректный запрос или недоступное время истории |
| 2 | Ошибка формулы или исключение во время шага |
| 3 | Превышен бюджет подшагов/CCD либо поиск столкновения не сошёлся |
| 4 | Некорректное численное состояние |

После ошибки шага 2–4 требуется `reset`. Не меняйте номера, порядок полей и экспортируемые функции при внутреннем рефакторинге.

## Как вносить изменения

Новую геометрию добавляйте в `geometry.cpp` и построение контакта. Новый тип связи — в отдельную функцию внутри `constraints.cpp` и её диспетчер. Закон силы — в соответствующий этап `solver.cpp`; импульсы проводите через `applyImpulse`, чтобы измеряемые силы оставались согласованы с движением. Новое редактируемое поле требует согласованного изменения протокола и Worker, поэтому это отдельная задача от рефакторинга ядра.

Изменение закона проверяйте сценой с известным результатом: свободное падение, столкновение, равновесие, баланс импульса или энергии. Для рефакторинга сравнивайте одинаковые сцены до и после. `tests/runtime.cpp` проверяет независимость экземпляров, историю, сброс и траектории; `tests/rest.cpp` — остановку и возобновление движения. `tests/stability.cpp` проверяет покой стопки, отсутствие ползучести после падения на склон, равномерное и ускоренное скольжение прямоугольника, стабильность точек приложения сил и сохранение реальных малых ускорений. Проверки фронтенда дополнительно прогоняют собранный WASM и настоящий Worker.

Форматирование: `clang-format -i engine/src/*.hpp engine/src/*.cpp engine/tests/*.cpp`. Настройки находятся в `engine/.clang-format`. Объяснения алгоритмов и ограничения храните в этом документе; код пишется без комментариев.

### Крепления пружин и жёсткие сборки

Связь `SpringGuide` (13) ограничивает поперечное смещение концов пружины, оставляя свободным растяжение. Фронтенд создаёт такую связь для каждого конца без подшипника. `referenceAngle` задаёт направление направляющей; `pulley = 0` означает направление относительно тела A, `-1` — относительно мира. Формат и размер буферов не меняются. Импульсы направляющей учитываются как реакции пружины, включая момент крепления. Подшипник снимает соответствующую направляющую.

Тела, соединённые цепочкой сварных связей, не сталкиваются между собой. Прямые шарнирные пары также исключаются, но отдельные части шарнирного механизма сохраняют коллизии.

Рычаги (стержни) и безмассовые пружины не участвуют в коллизиях. Рычаг сохраняет массу, инерцию и связи; поверхности и другие тела не блокируют его движение. Они также исключены из поиска CCD.

Для сварного соединения линейные и угловое ограничения решаются совместно с учётом плеч креплений. Это предотвращает расхождение концов из-за последовательных поправок положения и угла под нагрузкой.
